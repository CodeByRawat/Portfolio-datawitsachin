<p class="lede">To design an app from scratch with the least cost: <strong>focus on one core problem and one main user flow</strong>, <strong>sketch on paper</strong>, build <strong>wireframes and a clickable prototype in Figma's free plan</strong> using <strong>free UI kits</strong> (Material Design, Apple's iOS kits), <strong>test with 5 real users</strong> before any code, keep a <strong>simple design system</strong> (a few colours, one font, reusable components), and only then build with <strong>no-code or cross-platform tools</strong>. Changing a design is cheap; changing code is expensive.</p>

## Step 1: Define the problem and users

Write a one-sentence purpose: "Help clinic patients book and manage appointments in under a minute." List your primary user and their top 3 tasks.

## Step 2: Map the core flow

Draw the main journey as boxes: Open app → Choose service → Pick time → Confirm → Reminder. Anything not on this path is "later".

## Step 3: Sketch on paper

Fast, free and disposable. Sketch each screen in the flow. Try 2–3 layouts for the key screen.

## Step 4: Wireframes (low fidelity)

In **Figma (free plan)**, create grey-box layouts focusing on structure, hierarchy and content, not colours.

## Step 5: Use free UI kits and patterns

- **Material Design 3** kit (Android/web)
- **Apple iOS UI Kit** (official Figma kit)
- Community UI kits and icon sets (Material Symbols, Lucide)
- Follow familiar patterns (tab bars, bottom sheets, standard forms): users already know them, and they're cheaper to build

## Step 6: Simple design system

- **Colours:** primary, neutral, success, error (check contrast)
- **Typography:** one font family, 4–5 sizes
- **Spacing:** consistent scale (4/8/16/24/32)
- **Components:** buttons, inputs, cards, lists reused everywhere

## Step 7: Clickable prototype

Link screens in Figma's prototype mode so users can tap through the flow on a phone.

## Step 8: Test with users (cheaply)

- Recruit 5 target users (friends of customers, communities)
- Give tasks ("Book a cleaning next Tuesday")
- Watch where they hesitate; don't explain
- Fix issues and test again

Five users typically reveal most major usability problems.

## Step 9: Accessibility basics

Readable text (16pt+), sufficient contrast, large tap targets (~44–48px), labels for icons, support for system font sizes and dark mode where possible.

## Step 10: Handoff and build

Use Figma's Dev Mode or inspect panel for specs; export assets as SVG/PNG. Build with low-cost options: no-code (FlutterFlow, Adalo), cross-platform code, or a web app first (see [How to make an app](/blog/how-to-make-an-app/) and [How hard is it to make an app?](/blog/how-hard-is-it-to-make-an-app/)).

## Ways to save money

| Tip | Saving |
|---|---|
| Design only the MVP flow | Fewer screens to design and build |
| Use standard components | Faster development |
| Prototype and test before coding | Avoid expensive rework |
| Use free kits and icons | No asset costs |
| Start as a web app/PWA | One codebase, no app store fees initially |
| Hire a designer for key screens only | Professional polish where it matters |

## Frequently asked questions

### How do I design an app from scratch?
Define the problem and users, map the core flow, sketch screens, create wireframes and a clickable prototype in Figma, test with users, refine, then hand off for development.

### What is the cheapest way to design an app?
Use Figma's free plan, free UI kits and standard patterns, design only the MVP flow, and test prototypes before writing code.

### Do I need a designer to make an app?
Not for simple apps if you use UI kits and standard patterns; a designer helps with polish, branding and complex flows.

### What tools are used to design apps?
Figma is the most popular; others include Sketch, Adobe XD, Penpot (open source) and paper for early sketches.

### How long does it take to design an app?
A simple MVP prototype can take a few days to two weeks; complex apps take longer.

### Should I design for iOS or Android first?
Design for your primary audience's platform, using shared patterns so the design adapts to both.
